# SmartC Studio — Speaking the Community's Languages

Status: draft 2026-09-29
Branch: `feature/i18n`, cut from `feature/editor-polish` at `33cd510` (it needs
`language-definitions/api-functions.ts`); rebased onto `development` once
editor-polish is merged.

## Goal

Studio speaks English only. A large part of the Signum community — Russian-,
Ukrainian- and Chinese-speaking developers in particular, but also German,
Portuguese, French, Spanish and Italian speakers — works in a second language
the moment it opens the app.

This spec makes every piece of Studio's own text translatable — the chrome,
dialogs, toasts, wizards, help pages, and the editor documentation shown in
hover, completion and signature help — and ships it in nine languages. Adding a
tenth must be a matter of copying a folder, translating it, and adding one line.

## Languages

`en` (source and fallback), `de`, `pt-BR`, `fr`, `es`, `it`, `uk`, `ru`, `zh-CN`
(Simplified Chinese).

## Out of scope

- **Compiler messages.** They come from `smartc-signum-compiler`, are outside
  our control, and stay English.
- **Code.** Identifiers, API function names, opcodes, `#pragma`/`#include`
  names, and comments in example or template contracts.
- **A `?lang=` URL parameter.** Not needed.
- **Right-to-left languages.** None of the nine is RTL; adding one would be its
  own project.
- **Live language switching.** Switching reloads the page (see Boot).

## Verified ground truth

Read out of the current code, not assumed:

- **No i18n exists.** All text is inline English across ~10k lines of TSX in
  `src/features/*` (7 features), `src/pages/*` and `src/components/ui/*`.
- **Number formatting is ad hoc.** `components/ui/amount.tsx:32` uses
  `Intl.NumberFormat(navigator.language)`; `asm-editor/meta-data-view/contract-summary.tsx:157`
  and `meta-data-view.tsx:59` call `toLocaleString()` without a locale.
- **Editor documentation is module-level data.** `smartc-editor/language-definitions/`
  holds `api-functions.ts` (73 `api(...)`/`fixedApi(...)` entries, each with
  `detail`, `documentation` and per-parameter docs), `functions.ts` (built-ins),
  `directives.ts` (20 directives) and `keywords.ts`. These objects are built
  when the module is imported.
- **`App` is imported statically** by `src/index.tsx`, which renders
  immediately. Any `t()` evaluated at import time would run before a locale is
  loaded.
- **Code splitting is on.** `build.ts:154` sets `splitting: true`, so a dynamic
  `import()` per locale becomes its own chunk.
- **Autosave is debounced.** `components/ui/editor/use-editor-file.ts:33`
  waits `AUTOSAVE_PAUSE_MS = 800` before saving. A reload inside that window
  would drop the last edits.
- **Theme is applied by React.** `next-themes` (`App.tsx:18`, `attribute="data-theme"`)
  sets `data-theme` only once React runs; before that the page has no climate.
- **Fonts.** Exo 2 and JetBrains Mono (Google Fonts, `styles/globals.css:1`)
  cover Cyrillic; none of the loaded fonts covers CJK. Orbitron (Latin only) is
  used once, for the brand wordmark in `left-sidebar.tsx:126`, which is not
  translated.

## Design

### Module layout

```
src/i18n/
  locales.ts        LOCALES: { id, nativeLabel, load: () => import("./locales/<id>") }[]
  runtime.ts        t(), activeLocale(), formatNumber(), formatDate()
  boot.ts           resolveLocale(), activate(locale)
  T.tsx             <T k components /> — text with embedded elements
  switch.ts         switchLocale(id): flush saves, persist, reload
  keys.ts           key/param types derived from the English JSON
  GLOSSARY.md       terminology per language
  locales/
    en/ index.ts common.json home.json project.json workflow.json
        simulator.json testbed.json smartc-editor.json asm-editor.json
        editor-docs.json
    de/ …same files…
    pt-BR/ fr/ es/ it/ uk/ ru/ zh-CN/
```

Namespaces follow `src/features/`; `common` holds layout, `components/ui` and
page-level text. Whoever changes a feature touches that feature's JSON only.
Each locale's `index.ts` imports its JSON files and exports one object keyed by
namespace. English is imported statically by `runtime.ts`; every other locale
only through `LOCALES[i].load`.

JSON is the file format because Crowdin and Weblate read it as-is, so a later
move to a translation platform needs no restructuring.

### Boot

`src/index.tsx` becomes:

1. `resolveLocale()` — `localStorage["studio.locale"]` if it names a known
   locale; else the first of `navigator.languages` that matches (exact, then by
   language: `pt*` → `pt-BR`, `zh*` → `zh-CN`, `de-AT` → `de`); else `en`.
2. `await activate(locale)` — loads the chunk (no-op for `en`), sets
   `document.documentElement.lang`, arms `t()`. If the import fails (offline,
   stale deploy), log a warning and continue in English. Boot never hangs on a
   locale.
3. `const { App } = await import("./App")` — **after** activation, so every
   module that evaluates `t()` at import time (the editor documentation) sees
   the active locale.
4. `createRoot(elem).render(...)`, replacing the splash. `Crypto.init` and the
   HMR branch stay as they are.

The first render is already in the chosen language: there is no English frame
followed by a re-render.

### Splash

`index.html` gets, inside `#root`, the logo and nothing else. React replaces it
on first render.

- It becomes visible only after a 150ms `animation-delay`; a fast boot never
  shows it.
- Once visible, the logo breathes (a slow opacity/scale pulse). The motion is
  bound to one event — Studio starting — and ends with it, in keeping with
  `motion.css`. Under `prefers-reduced-motion: reduce` it stands still.
- An inline script in `<head>` copies `next-themes`' stored theme
  (`localStorage["theme"]`, default `nexus`) onto `data-theme` before first
  paint, so the splash and the first frame already wear the right climate.
- The splash styles are inline in `index.html`: the Tailwind bundle is not
  loaded yet when it shows.

### Switching language

A locale picker sits next to the climate switch. Each language is offered in its
own name ("Deutsch", "Português (Brasil)", "Українська", "Русский", "简体中文"…);
the active one is marked. Choosing one calls `switchLocale(id)`:

1. Flush pending autosaves. `use-editor-file.ts` registers its debounced save in
   a small module-level registry (`registerPendingSave(flush) → unregister`);
   `switchLocale` awaits every registered `flush()`.
2. Write `localStorage["studio.locale"]`.
3. `location.reload()`.

File contents already live in IndexedDB and metadata in `localStorage`, so a
reload after the flush loses nothing. Only locales listed in `LOCALES` are
offered; a locale is added to `LOCALES` once its translation exists, so nobody
can pick an empty language.

### `t()`

```ts
t("simulator.toolbar.step")
t("project.files.count", { count: 3 })
t("deploy.fee", { amount: "0.25" })
```

- **Typed keys.** `keys.ts` derives the key union from the English JSON
  (`"namespace.path.to.leaf"`). A typo is a compile error.
- **Typed parameters.** `{name}` placeholders in the English string become
  required parameters of that key.
- **Lookup:** active locale → English → the key itself. The UI never breaks;
  at worst it shows English.
- **Default.** Before `activate()` runs, the active locale is English. Every
  existing test therefore keeps running in English with no setup.
- **Plurals.** A leaf may be an object of CLDR categories:
  `{ "one": "{count} file", "other": "{count} files" }`. When `count` is passed,
  the category comes from `new Intl.PluralRules(activeLocale).select(count)`,
  falling back to `other`. Russian and Ukrainian use `one/few/many/other`,
  Chinese only `other`.
- **Interpolation** replaces `{name}` with `String(value)`; no HTML is ever
  produced by `t()`.

**Rule:** components call `t()` during render, never at module top level.
Module-level lists that carry labels (e.g. `CLIMATES[i].label`) store a key and
translate where they are rendered. The editor documentation is the one sanctioned
import-time use, made safe by step 3 of Boot.

### `<T>` — text with embedded elements

```tsx
<T k="simulator.help.intro" components={{ code: <code />, link: <a href={DOCS_URL} /> }} />
```

with `"intro": "Press <code>F10</code> to step. See the <link>manual</link>."`.
Translators see the whole sentence and may reorder it. `<T>` only recognises
the tag names passed in `components`, with no attributes and no nesting beyond
one level; everything else renders as literal text. Nothing is parsed as HTML.

### Formatting

`formatNumber(value, options?)` and `formatDate(value, options?)` use the
active locale. `amount.tsx` and the two `toLocaleString()` calls move to them.
Addresses, hashes, code sizes in hex and SIGNA values as the chain writes them
stay unformatted.

### Editor documentation

Signatures, return types, arity, include tables and register semantics stay in
TypeScript. Only prose moves to `editor-docs.json`, keyed by symbol name:

```json
{
  "api":        { "Get_A1": { "detail": "…", "doc": "…", "params": { "addr": "…" } } },
  "builtins":   { "sendAmount": { "detail": "…", "doc": "…", "params": { … } } },
  "directives": { "description": { "detail": "…", "doc": "…" } },
  "keywords":   { "…": { "doc": "…" } }
}
```

`declare(...)` in `api-functions.ts` and its counterparts in `functions.ts`,
`directives.ts` and `keywords.ts` take the symbol name and read `detail`, `doc`
and `params` through `t()`. Markdown in these strings is kept: Monaco renders it.

### Tests

In `bun test`, next to the code they check:

1. **Editor docs are complete (hard).** Every symbol in the language
   definitions has an English entry with `detail` and `doc`, every declared
   parameter has a parameter doc, and `editor-docs.json` has no entry without a
   symbol.
2. **Locales are consistent** — for every non-English locale, compared to
   English:
   - **fails** on a key English does not have;
   - **fails** when a string's `{placeholders}` differ from English;
   - **fails** when its `<tag>` names differ from English;
   - **fails** when its backtick code spans differ from English (so `Get_A1`
     cannot be "translated");
   - **fails** when a plural object lacks `other`;
   - **reports, does not fail,** missing keys — English covers them.
3. **Runtime** — lookup order, fallback, interpolation, plural selection for
   `en`, `ru` and `zh-CN`, `<T>` with known, unknown and reordered tags,
   `resolveLocale()` for stored, browser-matched and unknown locales.
4. **`switchLocale`** — pending saves are flushed before the reload.

### `bun run i18n:report`

A script printing, per locale, how many keys are translated out of English's
total, per namespace, and listing the missing ones with `--missing <locale>`.
It is what a community contributor runs before and after a PR.

### Glossary

`src/i18n/GLOSSARY.md` fixes terminology before any translation is written:

- **Never translated:** SIGNA, Signum, SmartC, AT, Studio's product name, API
  function names, opcodes, directive names, file extensions.
- **Fixed per language:** smart contract, deploy, testbed, scenario, simulator,
  breakpoint, step, compile, activation amount, fee, and the names of the
  workflow stages — one agreed term per language, so nine languages do not
  drift.

Translations follow it; reviewers change it rather than individual strings.

## Migration

Every phase is mergeable on its own: the English fallback means a half-migrated
app never shows a broken string.

1. **Infrastructure.** `src/i18n/*`, boot, splash, theme script, picker,
   `switchLocale` and the save registry, `<T>`, tests, `i18n:report`. `LOCALES`
   holds `en` only; nothing changes for anyone.
2. **Extraction, one commit per feature:** common/layout → home → project →
   workflow → simulator → testbed → smartc-editor → asm-editor, each with its
   pages. Strings become `t()`/`<T>`, English JSON is created, existing tests
   stay green.
3. **Editor documentation.** Prose moves out of `language-definitions/*` into
   `editor-docs.json`; test 1 goes in.
4. **Translations.** Glossary first. Then per locale, all namespaces:
   `de` first (evolver and the_tank review it early and sharpen the glossary),
   then `ru`, `uk`, `zh-CN`, then `pt-BR`, `fr`, `es`, `it`. Each locale joins
   `LOCALES` in the commit that completes it.
5. **README:** "Adding a language" — copy `locales/en`, translate, add the
   `LOCALES` entry, run `i18n:report` and the tests.

## Verification in the browser

With `de`, `ru` and `zh-CN` active, the main screens are checked by eye: home,
files, the SmartC and ASM editors (including hover and completion), simulator,
testbed, deploy wizard.

- **Length.** German and Russian run ~30% longer than English. Toolbars, the
  sidebar, the workflow rail and buttons must truncate or wrap cleanly, never
  overflow.
- **CJK.** No loaded font covers Chinese; the system fallback must render
  cleanly next to Exo 2 and JetBrains Mono. If it does not, add a CJK family to
  the font stacks (`globals.css:113`, `:220`).
- **Boot.** A throttled network shows the splash in the right climate and then
  the app in the chosen language, with no English frame.
- **Switch.** Typing in an editor and switching language immediately keeps the
  last keystrokes.
